# ParcelScope — Discovery & Roadmap

## Discovery objective

ParcelScope is being validated through workflow discovery with real-estate professionals.

The goal is not to ask, “Do you like this app?”

The goal is to understand:

- What property-research work happens today
- Which tools are used
- Where information gets re-entered
- Which tasks consume the most time
- Which information must be authoritative
- What breaks under auction-day time pressure
- Which proposed features have enough value to justify building

## Current prototype workflow

A current demonstrated path is:

```
Import auction/property list
        ↓
Open parcel
        ↓
Retrieve county parcel record and boundary
        ↓
Compare map/imagery
        ↓
Open official research sources
        ↓
Save notes / watchlist / max-bid scenario
        ↓
Return to list
        ↓
Export supported research
```

## Discovery questions

Current discovery asks users to walk through a real recent research task.

Topics include:

- Property type and customer segment
- Existing MLS/RPR/GIS/spreadsheet/CRM workflow
- Most time-consuming step
- Hardest information to verify
- Properties researched per week/month
- Time spent per property
- Existing paid tools
- Client deliverables
- Field/mobile needs
- Auction-list format and change handling
- Auction-day speed and information pressure
- Follow-up after auction
- Willingness to test a revised prototype

## Evidence discipline

Research separates:

- Observed behavior
- Direct customer statements
- Proposed ideas
- Unvalidated assumptions

A feature request is not automatically a roadmap commitment.

The decision framework is:

**Build now / Validate further / Do not build yet**

## Current hypotheses — not promises

Potential future capabilities being tested include:

- Client folders and buyer criteria
- Side-by-side property comparison
- One-click sourced property reports
- Cross-device/cloud synchronization
- Field notes and photo attachments
- Secure client/team sharing
- Better property-risk summaries
- MLS/CRM integrations where licensing allows
- Additional auction-specific workflow support

None of these should be represented as implemented unless they are verified in the current product.

## Agent/realtor workflow hypothesis

A possible future agent workflow is:

```
Client brief
→ shortlist properties
→ open official parcel maps/records
→ compare due diligence
→ attach visit notes
→ assemble sourced client packet
→ share securely
→ follow up
```

This remains a product hypothesis under discovery.

## Auction workflow hypothesis

ParcelScope is also testing problems across three auction phases:

### Before auction

- Find and clean auction lists
- Identify parcel IDs
- Research properties
- Check official sources
- Save maximum-bid assumptions
- Track list changes

### During auction

- Locate the called parcel quickly
- Confirm parcel identity
- View saved notes and bid ceiling
- Handle poor signal or changing lists
- Avoid acting on the wrong parcel

### After auction

- Track outcomes
- Track deadlines
- Continue due diligence
- Preserve research and communication

## Current product principle

ParcelScope should not become another tool that creates more tabs and duplicated data.

The product should earn its place by reducing a measurable part of the research workflow.

## What would justify building next

A feature moves forward when discovery supports:

- Recurring pain
- Meaningful time/risk reduction
- Clear user value
- Feasible source/integration access
- Acceptable trust/security model
- Evidence that the feature belongs in ParcelScope rather than an existing system

## Pricing

Any prices discussed during discovery are hypotheses, not finalized commercial plans.

Pricing should follow validated workflow value rather than precede it.

## Current status

This project is active.

The current goal is to collect enough workflow evidence to choose the next narrow product increment, rather than expanding the prototype in every possible direction.
