# ProductTrace — Portfolio Screenshot Plan

Capture these screenshots from the live ProductTrace app after development freeze.

## Core V1

1. **Evidence Inbox**
   - show representative evidence records
   - include source labels / excerpts where visible

2. **AI Analysis**
   - show grounded themes with evidence references
   - prefer a view where confidence and citations are visible

3. **Opportunity Board**
   - show AI proposal vs PM decision / rationale
   - demonstrate Accept / Modify / Reject / Defer controls

4. **Experiment Builder**
   - show hypothesis, primary metric, guardrails, expected outcome, decision threshold

5. **Instrumentation Plan**
   - show event definitions / mappings
   - capture the Planned only telemetry label and synthetic-validation distinction if visible

6. **Eval Center**
   - capture Run 1 and Run 2 comparison if possible
   - highlight 65% → 95% and 100% grounding

7. **Launch Gate**
   - capture all criteria passing
   - show final PM approval separately from eligibility criteria

8. **Decision History**
   - show before / after decision state and PM rationale

## Market Intelligence

9. **Research Brief**
   - show decision question and research scope

10. **Market Sources**
   - show official source URL, exact excerpt, verification, freshness

11. **Competitor Profile**
   - show claim-level source provenance
   - avoid screenshots that imply automated rankings

12. **Market Themes**
   - show the three AI-generated themes and PM statuses

13. **Market Opportunity**
   - show original AI proposal, PM-modified wording, and supporting claims

## Discovery Criteria

14. **Discovery Record Overview**
   - source Market Opportunity linkage
   - In Discovery status

15. **Discovery Readiness**
   - show dimension-by-dimension readiness rather than an overall score

16. **More Discovery Needed Decision**
   - show PM rationale and unresolved Root Cause / Value gaps

17. **Research Package**
   - interview guide / workflow observation / concept-test artifacts

18. **Research Entry UI**
   - finding-entry form
   - falsification statuses: Untested / Supported / Not Supported / Mixed

## Screenshot quality rules

- use the same browser size across screenshots
- crop browser chrome where possible
- avoid personal or sensitive data
- use only evidence already approved for the portfolio
- do not show secrets, API keys, or internal environment values
- make sure demo/synthetic labels remain visible where relevant
- do not crop away evidence provenance just to make the screen cleaner
